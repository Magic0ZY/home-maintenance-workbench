# 依赖与运行环境清单

**一句话结论：本项目运行时不依赖任何第三方库，没有构建步骤，克隆下来就能看。**

---

## 一、依赖总览

### ✅ 运行时依赖：无

| 检查项 | 结果 |
|---|---|
| `package.json` | ❌ 不存在 |
| `node_modules` | ❌ 不存在 |
| 构建/打包工具 | ❌ 无 |
| 外部 JS/CSS 库 | ❌ 无（jQuery / Vue / React / Tailwind 全都没用） |
| 字体文件 | ❌ 无（用系统字体栈） |
| 包管理器 | ❌ 不需要 |

整个应用就是**一个 HTML 文件**，所有 CSS 和 JS 都内联在里面。

唯一的"外部依赖"是平台注入的 SDK：

```html
<script src="/page/page_comm/inject.js"></script>
```

这个文件由平台在托管环境下自动提供，向页面注入 `window.__SMART_PAGE__.database`。**本地开发时这个请求会 404，但不影响运行**——页面检测不到 SDK 就自动进入"离线预览"模式。

### ⚙️ 开发/辅助依赖（可选）

| 工具 | 版本 | 用途 | 是否必需 |
|---|---|---|---|
| Python | 3.8+ | 本地数据处理脚本、批量备份/恢复、截图命令编排 | 可选 |
| Chrome / Edge | 任意近期版本 | 仅用于无头截图生成演示图 | 可选 |
| Git | 任意 | 拉代码 | 可选（也可直接下载 ZIP） |

**注意：Python 和 Node.js 都不是项目运行所必需的**，只在你想跑辅助脚本时才需要。

## 二、浏览器环境要求

### 最低要求

| 能力 | 要求 | 用途 |
|---|---|---|
| ES5 | 必需 | 代码全部用 `var` / `function`，未使用 ES6+ 语法 |
| Promise | 必需 | 数据层全部基于 Promise 链 |
| `localStorage` | 必需 | 存当前成员身份、祝福去重标记 |
| `Array.prototype.forEach/map/filter` | 必需 | 常规数组操作 |
| CSS Transitions | 必需 | 弹层动画 |
| CSS Flexbox | 必需 | 主要布局方式 |
| CSS Grid | 不需要 | 未使用 |
| Fetch / XHR | 不需要（页面本身不发网络请求） | — |

### 兼容性说明

代码刻意保持保守的语法风格，**没有使用任何 ES6+ 特性**：

- 不用箭头函数（全用 `function () {}`）
- 不用 `let` / `const`（全用 `var`）
- 不用模板字符串（全用字符串拼接）
- 不用解构、展开运算符、`class`、`async/await`

因此兼容性极好，**理论上 IE11 之后的任何浏览器都能跑**（当然实际用不到那么老的环境）。

## 三、平台环境（完整版部署需要）

如果你只想跑离线演示，**本节可以跳过**。

### 必需

| 能力 | 说明 |
|---|---|
| WorkBuddy 账号 | 提供数据表和页面托管 |
| 一个空间（Space） | 数据表和页面的容器，需要记下空间 ID |
| 数据表服务 | 提供 17 张表（或最小 7 张）的存储与查询 |
| 页面托管服务 | 托管单文件 HTML，支持"事务式"上传 |

### 可选

| 能力 | 说明 |
|---|---|
| 云端自动化任务 | AI 定时巡检。不配也能用，只是少了自动判断能力 |
| 数据表分享 | 给家人开"查看"权限，这是真正的权限边界 |

### 平台 SDK 接口契约

页面依赖的 SDK 接口如下（这是本项目对宿主环境的最小要求）：

```js
window.__SMART_PAGE__ = {
  database: {
    // 分页查询
    query({ databaseId, pageSize, startCursor })
      → Promise<{ records: [], hasMore: bool, nextCursor: string }>

    // 读表结构（用于取 select 选项）
    getSchema({ databaseId })
      → Promise<{ properties: [{ name, type, config: { options: [{ text }] } }] }>

    // 单条读取
    getRecord({ databaseId, recordId })
      → Promise<{ record }>

    // 增删改
    addRecord({ databaseId, properties })       → Promise<{ record }>
    updateRecord({ databaseId, recordId, properties }) → Promise<{ record }>
    deleteRecord({ databaseId, recordId })      → Promise<{}>

    // 图片上传
    uploadImage({ file })                        → Promise<{ url }>

    // 数据变更订阅
    onUpdated(callback)                          → void
  }
};
```

**如果你要把这个项目移植到别的平台**，只要实现这 8 个方法，页面代码完全不用改。`demo/mock4.js` 就是一个约 150 行的参考实现。

> 这意味着**项目本质上不绑定特定平台**。页面只认这个接口契约，谁实现都行——自己写个后端，或者换成 SQLite + 本地服务，都可以。

## 六、性能与环境注意事项

### 网络与并发

- **页面加载零外部请求**（除了平台的 `inject.js`），首屏极快
- **数据表查询必须分批**。教训：最初用 `Promise.all` 并发读 7 张表没问题，加到 16 张时**直接被限流，全部失败**。现在每批 4 张 + 单表重试。
- 单次查询 `pageSize` 设 100，超出走游标翻页

### 读表的成本警告

这是本项目**最贵的教训之一**：

> 一次性把整表的长文本字段读回来，**会直接导致云端任务失败**。

实际事故：「数据快照」表累积到 7.7 万字符时，一次整表读取让连续两轮定时巡检都失败。

**规则**：
- 能用字段投影就只用需要的列
- 判断"该不该做某事"的读取，改成"字段投影 + 只取最近一条"
- 读之前先想清楚"这张表会不会很大"

### 存储

`localStorage` 只存三类极小数据：

| key | 内容 |
|---|---|
| `wb_home_maint_user` | 当前成员名（字符串） |
| `wb_bless_<日期>` | 今天已弹过祝福的标记 |
| `wb_admin_*` | 管理员解锁状态 |

总量不超过几 KB。

### 时区

**这是最容易出错的地方**，单独强调：

- 平台按**写入时的字面值**回读，**页面不做任何时区位移**
- `dtLocal()` 只做格式化，不换算
- 写入方（人 或 AI）必须**一律写北京时间**
- 踩过的坑：AI 把下午 15:52 按 UTC 写入，页面显示 07:52，差了 8 小时

> 如果你在别的时区使用本项目，需要自行调整"什么算今天"的判断基准（`todayStart()`）。

## 七、故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 界面全空，左下角显示"离线预览" | 没有平台 SDK（正常） | 如果你想看数据，用 `demo/demo5.html` |
| 显示"3 张表未加载 · 点重试" | 并发限流或网络抖动 | 点重试；持续失败检查网络 |
| 链接打开报 `NoSuchKey` | url 字段没走 `valLink()` 转换 | 检查渲染代码，确认过 `docLink()` |
| 日期显示差 8 小时 | 写入时按 UTC 写了 | 改为写北京时间；页面不应做补偿 |
| 定时任务报"执行失败" | 步骤预算耗尽（常见于读了太多表） | 检查是否整表读取了长文本字段 |
| 上传页面报 `transaction not found` | 事务开太久失效 | 重新开事务再上传 |
| 游客模式改不了数据 | 设计如此 | 切换到正式成员身份 |
