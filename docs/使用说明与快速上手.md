## 第一节：五分钟看个大概（纯浏览）

### 步骤

```bash
git clone <this-repo>
cd <this-repo>/demo
```

然后**双击 `demo5.html`**（或右键用浏览器打开）。

Windows 用户也可以：

```bash
start demo5.html
```

macOS 用户：

```bash
open demo5.html
```

### 你会看到什么

一个手机尺寸的界面，底部 5 个 Tab：

| Tab | 内容 |
|---|---|
| **今天** | 待办聚合：到期的维护项、待缴费用、快用完的日用品、待准备的节日 |
| **维护** | 设备维护清单，带剩余天数倒计时和颜色分档 |
| **台账** | 固定费用 / 节日与生日 / 日用品库存 三个子模块 |
| **AI** | 任务信箱，可以写一句话布置任务 |
| **我的** | 成员切换、数据导出、快照备份 |

数据是虚构的示例家庭：扫地机器人、新风机、净水机、洗衣机，还有一袋猫砂。

**可以随便点**——加维护项、点"已更换"、标记费用已缴、在 AI 里写任务。数据存在浏览器内存里，刷新就恢复原样，改不坏。

### 左下角那行字

你会看到同步状态显示「**离线预览**」。这是设计好的降级模式：

```js
// 检测不到平台 SDK 时自动进入
var db = (window.__SMART_PAGE__ && window.__SMART_PAGE__.database) || null;
if (!db) { renderSync('off', '离线预览'); return; }
```

意思是"我在假数据上跑，没有连真实数据源"。看到这四个字是正常的。

## 第二节：本地跑通与改代码

### 2.1 环境检查

**不需要装任何东西。** 先确认这一点：

```bash
ls package.json    # 应该报"没有那个文件"——这是对的
```

确实没有。项目就是单个 HTML 文件。

### 2.2 文件说明

| 文件 | 说明 |
|---|---|
| `page_v9/index.html` | **主程序**，你要改的就是它 |
| `demo/mock4.js` | 假 SDK + 假数据，让主程序能在本地跑起来 |
| `demo/demo5.html` | 主程序 + 注入 mock4 的组合体 |

### 2.3 建立你自己的开发页

**推荐做法**：不要让 `demo5.html` 和主程序脱节。做法是这样——

```bash
# 1. 复制主程序到 demo 目录
cp page_v9/index.html demo/mytest.html

# 2. 在 mytest.html 的 head 里，主脚本之前，插入 mock
```

打开 `demo/mytest.html`，找到这一行（大约在第 4 行）：

```html
<script src="/page/page_comm/inject.js"></script>
```

在它**后面**加一行：

```html
<script src="mock4.js"></script>
```

保存，用浏览器打开 `demo/mytest.html`。

**为什么要这样**：`inject.js` 在本地会 404（平台不提供），所以 `__SMART_PAGE__` 是空的；`mock4.js` 补上它，页面就以为自己在正常云端模式。**顺序不能反**——mock 必须在主脚本之前执行。

### 2.4 改代码验证循环

改 `demo/mytest.html` → 刷新浏览器 → 看效果。就这样，没有编译、没有热重载。

改完确认没问题后，把改动**同步回 `page_v9/index.html`**（不要直接把 mytest.html 复制回去，因为它带有 mock 注入）。

### 2.5 建议装的辅助工具

如果你想更高效：

| 工具 | 用途 |
|---|---|
| 浏览器 DevTools | 必备。Console 看报错，Elements 看渲染，Application 看 localStorage |
| VS Code + Live Server | 改完自动刷新，省一次手动刷新 |
| Python 3.8+ | 只在跑批量数据脚本时需要 |

### 2.6 便于阅读的代码快照

`page_v9/_s0.js` 是把主脚本（`<script>` 标签内的 JS）单独抽出来的文件，**约 1,027 行**。用编辑器打开它，语法高亮和跳转都比在 HTML 里舒服。注意它只是快照，改它不生效。

### 2.7 阅读顺序建议

不要从头读到尾。按这个顺序：

```
1. 配置块（DB / MF / FALLBACK_OPTS）   → 知道有什么表、什么字段
2. Store（数据层）                      → 知道数据怎么进来
3. HUB.FEE（一个完整的声明式 CRUD 例子） → 理解套路
4. boot()（文件末尾）                    → 理解启动顺序
5. 其余渲染函数按需查
```

详细导览见 [`项目结构说明.md`](项目结构说明.md)。

### 2.8 常见的第一个实验

改一下提醒阈值，看看效果。搜索 `mStatus`：

```js
function mStatus(rec) {
  var d = daysLeft(rec);
  if (d === null) return { key: 'na', text: '—' };
  if (d <= 0)  return { key: 'over', text: '逾期 ' + (-d) + ' 天' };
  if (d <= 7)  return { key: 'soon', text: d + ' 天后' };
  if (d <= 14) return { key: 'near', text: d + ' 天后' };
  return { key: 'ok', text: d + ' 天后' };
}
```

把 `d <= 7` 改成 `d <= 3`，刷新，看看有多少条从"快到期"变成了"临近"。这就是整个项目的基本工作方式。

### 2.9 一个重要的自检习惯

**改完之后跑一遍语法校验**，因为单文件里语法错误会导致整个页面白屏，而且报错信息不好定位：

```bash
# 用 node 检查抽出来的 JS 语法
node --check page_v9/_s0.js
```

或者用浏览器直接打开，看 Console 有没有红色报错。

## 第三节：部署到自己家的完整版

### 3.1 理解你要建什么

```
你的空间
├── 17 张数据表（放数据）
├── 1 个页面（放界面）
└── 1 个云端任务（放 AI，可选）
```

### 3.2 第 1 步：建数据表

**先建这 7 张**，这是最小可跑集合：

| # | 表名 | 关键字段 |
|---|---|---|
| 1 | 维护清单 | 维护项、所属设备、房间、类别、维护动作、周期天数、上次维护日期、耗材型号、备件库存、耗材单价、说明书链接、备注 |
| 2 | 维护日志 | 时间、类型、设备、维护项、操作人、说明、金额 |
| 3 | 固定费用台账 | 名称、类别、金额、缴费周期、下次应缴日、缴费渠道、状态、备注 |
| 4 | 节日与生日 | 名称、类型、日期、关联成员、提前提醒天数、AI行程推荐、联动采购、备注 |
| 5 | 日用品库存 | 名称、规格、囤货数量、存放位置、经验消耗天数、上次报备日期、状态、备注 |
| 6 | 任务请求表 | 任务类型、参数、状态、提交时间、完成时间、提交人、已读、结果 |
| 7 | AI任务注册表 | 指令全文、上次运行、待执行数 |

**字段类型要点**：

- `房间` / `类别` / `维护动作` / `状态` 等 → **单选项（select）**，选项值就是页面下拉框的内容
- `周期天数` / `备件库存` / `囤货数量` → **数字（number）**
- `耗材单价` / `金额` → **货币（currency）**
- `上次维护日期` / `下次应缴日` / `日期` → **日期（date）**
- `说明书链接` → **URL 类型**
- `说明书图片` → **图片类型**

> ⚠️ **一个必须提前知道的坑**：如果你先建了 `单选项` 字段并填了数据，后来删掉某个选项，**引用它的单元格会被静默清空**。所以选项要一次性想清楚。

> ⚠️ **房间清单的唯一来源是这个 select 字段的选项**。页面不硬编码房间名，全部从 schema 读。所以你增删房间，只需要改这个字段的选项。

剩下 10 张表（家庭账本、家庭成员、偏好设置、节日准备、数据快照、宠物档案、宠物护理、物品归档、存放位置、设备档案）可以后续按需建。完整字段定义见本文末[附录](#附录17-张表完整字段定义)。

### 3.3 第 2 步：改配置

打开 `page_v9/index.html`，找到配置块（约第 319 行）：

```js
var DB = {
  MAINT: '你的维护清单表ID',
  LOG:   '你的维护日志表ID',
  FEE:   '你的固定费用表ID',
  FES:   '你的节日与生日表ID',
  DLY:   '你的日用品库存表ID',
  TSK:   '你的任务请求表ID',
  REG:   '你的AI任务注册表ID'

```

**只用 7 张表的话，就只填这 7 个。** 页面对缺失的表有容错，不会崩。

然后检查 `MF` 常量是否和你的字段名一致：

```js
var MF = {
  NAME: '维护项',   DEV: '所属设备',  ROOM: '房间',     CAT: '类别',
  ACT: '维护动作',  CYCLE: '周期天数', LAST: '上次维护日期',
  URL: '说明书链接', IMG: '说明书图片', NOTE: '备注',
  MODEL: '耗材型号', STOCK: '备件库存', PRICE: '耗材单价'
};
```

如果你照搬了推荐的字段名，这里不用改。

### 3.4 第 3 步：上传页面

页面通过**事务**方式上传，四步：

```
1. create_page_transaction   → 开事务，拿事务 ID
2. get_page_upload_url       → 拿上传地址
3. PUT <上传地址>             → 上传改好的 index.html
4. commit_page_transaction   → 提交，生成新版本
```

上传成功后，页面地址形如：

```
https://<静态资源域名>/page/<nodeId>/<version>/index.html
```

> ⚠️ **事务有时效**。开事务后如果磨蹭太久才提交，会报 `transaction not found`。遇到就重开一个事务再传。这是个高频坑，别怀疑自己代码有问题。

### 3.5 第 4 步：初始化数据

页面首次打开会要求选身份。先建几条数据，让页面"活"起来：

**① 建家庭成员**

在「家庭成员」表里加几条：你、家人。之后打开页面时选身份进入。

**② 建几条维护项**

至少要有一条，否则"维护"页是空的。比如：

| 维护项 | 所属设备 | 房间 | 周期天数 | 上次维护日期 |
|---|---|---|---|---|
| 中效滤网 | 新风机 | 客厅 | 180 | 2026-03-20 |
| 尘袋 | 扫地机器人 | 客厅 | 60 | 2026-08-01 |

**③ 建几条固定费用**

| 名称 | 金额 | 缴费周期 | 下次应缴日 | 状态 |
|---|---|---|---|---|
| 物业费 | 3600 | 年 | 2026-12-31 | 待缴 |
| 采暖费 | 2800 | 年 | 2026-11-01 | 待缴 |

刷新页面，"今天"页就会自动算出该缴的费用。

### 3.6 第 5 步：配 AI 定时任务（可选）

**不配也能用**，只是少了自动判断能力。

配置分三部分：

#### ① 在「AI任务注册表」里存规则全文

建一条记录，把完整的巡检规则写进 `指令全文` 字段。

**为什么要存数据表不存任务里**：云端任务的输入框有长度上限，**实测约 1,455 字符，超出会静默截断**——不报错，就是默默少了后半段，非常危险。而完整规则约 7,600 字符。

所以采用**规则外置**：规则存表里，任务里只放一段短提示词。

#### ② 在任务里放元提示词

任务提示词只写这一句（约 1,200 字符）：

```
读取「AI任务注册表」中指令全文字段，按其中的规则执行本轮巡检。
```

规则内容改了就改数据表，**任务提示词永远不用动**。

#### ③ 设置频率

推荐 **6 小时**一次。

原因是页面已经覆盖了所有确定性提醒（到期、待缴、库存），AI 只需要处理"需要判断"的部分，不需要高频。

#### 门控机制

这是省钱的关键。AI 的第 0 步只做两次极廉价的查询：

```
读「任务请求表」中 状态=待执行 的条数
读「AI任务注册表」的 上次运行 时间

if (待执行 == 0 && 距上次运行 < 7 天) {
    return;   // 直接结束，约 2 步，不读表不写表
}
// 否则进入完整巡检
```

效果：**无事发生时一轮只花几百 token**，比全量巡检省约 95%。

> **为什么用"距上次运行 ≥7 天"而不是"每周一跑全量"**：门控本身不写数据，所以时间差判断天然幂等。如果按"每周一"触发，一旦频率调到每小时一次，周一就要全量跑 24 次。这个设计是被问出来的——"如果周一完全执行的话，改成 1 小时 1 次，岂不是周一要跑 24 次？"确实如此，所以改成了时间差。

### 3.7 第 6 步：验证

按这个顺序验收：

| # | 检查项 | 预期 |
|---|---|---|
| 1 | 打开页面 | 显示"已同步"，各 Tab 有数据 |
| 2 | 改一条维护项的"上次维护日期" | 剩余天数立刻变化 |
| 3 | 点"已更换" | 写维护日志 + 更新上次维护日期 |
| 4 | 点费用"已缴" | 状态回待缴 + 下次应缴日滚动一期 |
| 5 | 在 AI 页写一条任务 | 任务进入"待执行" |
| 6 | 手动跑一次定时任务 | 任务变成"已完成"，有返回结果 |
| 7 | 关掉再打开页面 | 数据还在（说明写库成功） |

第 7 项最重要——**能持久化**才算真的跑通。

### 3.8 权限设置

**这是真正的安全边界**，比页面上的密码锁重要得多：

| 角色 | 数据表权限 | 说明 |
|---|---|---|
| 你自己 | 编辑 | 管理员 |
| 家人 | **查看** | 只能看，改不了 |
| 游客 | 查看 | 同上 |

页面上那个"管理员密码"**不是安全机制**——任何人都能在浏览器控制台改 localStorage 绕过它。它只用于防止误操作（家人好奇点进来把数据删了）。

真正的防线是**数据表的分享权限**。给家人开"查看"，他们物理上就改不了数据。

### 3.9 备份

页面「我的」页有**一键快照**：把所有表的数据打成一条记录存进「数据快照」表，保留最近若干条。

> ⚠️ **加新表之后必须更新快照名单**。代码里有一个 `SNAP_NAMES` 数组列了要备份的表；如果加了新表却没加进去，**这张表就等于没有备份**。这个坑踩过。

另外可以定期用 `exportJSON()` 导出完整 JSON 到本地。

## 第四节：日常使用

### 日常操作

| 场景 | 操作 |
|---|---|
| 做了一次维护 | 「维护」页找到那条 → 点"已更换" |
| 想推迟 | 点"延后"，选新的日期 |
| 缴费了 | 「台账」→「固定费用」→ 点"已缴" |
| 日用品快用完了 | 「台账」→「日用品」→ 改状态为"快用完" |
| 买了新的囤货 | 改"囤货数量" |
| 想让 AI 干活 | 「AI」页写一句话，比如"帮我把新买的洗地机加进维护清单，滤网 90 天换一次" |

### AI 能做什么

AI 定时巡检时会做的事：

1. 读「任务请求表」里状态为"待执行"的任务，按意图执行
2. 检查节日是否进入准备窗口，生成准备事项
3. 汇总需要采购的耗材，生成采购清单
4. 把结果写回任务的"结果"字段

**AI 不会做的事**（故意的）：

- 不会自己新建维护项（设备没建档会报"未建档"，让你决定）
- 不会填没核实过的链接
- 不会读不到数据就当空

### 一句话布置任务的例子

在「AI」页写：

```
我买了个 XX 洗地机，放客厅，滚刷 60 天换一次，滤芯 90 天换一次，说明书链接我回头补。
```

AI 会解析出两条维护项，写进维护清单，并在结果里回复它做了什么、哪些信息缺失。

> 注意：**设备第一次出现时 AI 会报"未建档"** 而不是自己新建。这是故意的设计——避免 AI 乱建设备。你需要先在「设备档案」里建一条，或者明确告诉它"新建"。

### 字段值格式速查

**写入格式**（提交给 API）：

```js
{
  '维护项':       { text: '尘袋' },
  '周期天数':     { number: 60 },
  '耗材单价':     { currency: 39 },
  '上次维护日期': { date: '2026-09-01' },
  '房间':         { select: '客厅' },
  '标签':         { multi_select: ['耗材', '高频'] }
}
```

**读取格式**（API 返回）：

| 类型 | 返回形态 | 处理函数 |
|---|---|---|
| 文本 / 单选 | 字符串 | 直接用 |
| 数字 / 货币 | 数字 或 `{amount}` | `numOf()` |
| 日期 | `'2026-09-17T00:00:00Z'` | `parseDay()` |
| 多选 | **数组**（元素可能是对象） | 取 `.text` |
| URL | **数组** `[{link, text}]` | `docLink()` |
| 图片 | **数组** `[{imageUrl}]` | `imgUrlOf()` |
| 勾选 | 布尔 | 直接判断 |

> 🚨 **最后强调一遍**：URL 和图片字段都是**数组**。直接拼进 `href` / `src` 会渲染成 `[object Object]`，然后在浏览器里按相对路径解析，报 `NoSuchKey`。这个坑踩过，请务必用 `docLink()` / `imgUrlOf()` 转换。
