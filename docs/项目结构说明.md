# 项目结构说明

本文档逐层解释代码结构，目标是让你**在不读完 1,348 行代码的情况下**知道每一块在哪、干什么。

---

## 一、整体结构

项目只有**一个程序文件**：`page_v9/index.html`。它是完整的单文件应用——CSS、HTML、JS 全在里面。

```
page_v9/index.html  （约 75 KB / 1,348 行）
│
├── [第 1-6 行]    文档头 + 平台 SDK 注入

│                    appbar / 5 个视图 / tabbar / 弹层
```

主脚本内部按逻辑分成 9 个区块，导入顺序即依赖顺序：

## 二、配置常量（区块 ①）

```js
  FES:   'YOUR_FES_DB_ID',     // 节日与生日
```

> 演示用的 `demo/mock4.js` 里还有一个更完整的 `DB`，额外含 `LEDGER`（家庭账本）、`MEMBER`（家庭成员）、`PREF`（偏好设置）、`PREP`（节日准备）、`SNAP`（数据快照）等 12 个 ID。

### `MF` —— 维护清单的字段名常量

```js
var MF = {
  NAME: '维护项',   DEV: '所属设备',  ROOM: '房间',     CAT: '类别',
  ACT: '维护动作',  CYCLE: '周期天数', LAST: '上次维护日期',
```

## 三、工具函数（区块 ②）

挑几个关键的说明，因为**它们的写法本身就是为了绕坑**。

### `parseDay(v)` —— 日期解析

```js
function parseDay(v) {
  if (!v) return null;
  var s = String(v).slice(0, 10);     // '2026-09-17T00:00:00Z' → '2026-09-17'
  var p = s.split('-');
  if (p.length !== 3) return null;
  return new Date(+p[0], +p[1] - 1, +p[2]);   // 本地时区构造，不做位移
}
```

**关键**：API 回传的日期带 `T00:00:00Z` 后缀，但那是显示层怪癖——平台按**写入时的字面值**回读，页面**绝不做时区换算**。所以这里只做字符串截取 + 本地构造。

> 踩过的坑：AI 曾把下午 15:52 按 UTC 写进，页面显示成 07:52，差了 8 小时。改法不是让页面去补偿，而是**要求写入方一律写北京时间**。

### `numOf(v)` —— 数值提取

```js
function numOf(v) {
  if (v === null || v === undefined || v === '') return null;
  if (typeof v === 'number') return v;
  if (typeof v === 'object') {                    // 数字字段可能回传 {amount}
    if (v.amount !== undefined) return +v.amount;
    if (v.value !== undefined) return +v.value;
    return null;
  }
  var n = parseFloat(String(v).replace(/[^\d.\-]/g, ''));
  return isNaN(n) ? null : n;
}
```

number 和 currency 字段有时回传裸数字，有时回传 `{amount: 39}`。这个函数把两种形态统一。

### `docLink(v)` —— 链接安全提取

```js
function docLink(v) {
  // url 字段回传是数组：[{link: 'https://...', text: '说明书'}]
  if (Array.isArray(v)) {
    var f = v[0] || {};
    return String(f.link || f.url || f.text || '') || '';
  }
  if (v && typeof v === 'object') return String(v.link || v.url || '') || '';
  return String(v || '');
}
```

**这是最危险的一个字段类型**。url 字段回传的是数组，如果直接 `'<a href="' + v + '">'`，会渲染成 `[object Object]`，浏览器按相对路径解析，打开报 `NoSuchKey`。

> **铁律**：凡是渲染链接的地方，一律过这个函数。图片同理，要过 `imgUrlOf()`（image 字段回传 `[{imageUrl}]`）。

### `daysLeft(rec)` —— 剩余天数

业务核心。`周期天数 + 上次维护日期 → 剩余天数`：

```js
// 简化示意
var cycle = numOf(rec[MF.CYCLE]);
var last  = parseDay(rec[MF.LAST]);
if (!cycle || !last) return null;
var next = new Date(last.getTime() + cycle * 86400000);
var diff = Math.ceil((next - todayStart()) / 86400000);   // 正数=还有几天，负数=逾期
```

结果交给 `mStatus()` 分档：

| 条件 | 档位 | 颜色 |
|---|---|---|
| `diff <= 0` | 逾期 | 红 |
| `1 <= diff <= 7` | 快到期 | 橙 |
| `8 <= diff <= 14` | 临近 | 黄 |
| `diff > 14` | 正常 | 默认 |

## 四、成员与权限（区块 ③）

三层结构：

```js
function user() { return localStorage.getItem(USER_KEY) || ''; }   // 当前身份
function isGuest() { return !user() || user() === '游客'; }
function canWrite() { return !isGuest() && canWriteMore(); }        // 统一写守卫
```

**所有写操作的入口都要先过 `canWrite()`**。这是防止"新增功能忘了加权限"的统一关口。

管理员锁的定位要说清楚：

```js
function hashPw(s) { /* 简单哈希，不是加密 */ }
function adminTrusted() { /* 本次会话是否已解锁 */ }
```

**这不是安全机制**。任何人都能在控制台改 `localStorage`。它只用于防止**误操作**（比如家人好奇点进来把数据删了）。真正的安全边界是**数据表的分享权限**——给家人开"查看"权限，他们物理上就改不了。

## 五、数据层（区块 ④）

### `qAll(dbId)` —— 分页查询

平台单次查询有条数上限，所以必须翻页：

```js
function qAll(dbId) {
  var out = [], cursor = null;
  function step() {
    return db.query({ databaseId: dbId, pageSize: 100, startCursor: cursor })
      .then(function (res) {
        out = out.concat(res.records || []);
        if (res.hasMore && res.nextCursor) { cursor = res.nextCursor; return step(); }
        return out;
      });
  }
  return step();
}
```

### `Store` —— 全局数据仓库

```js
var Store = {
  rows: {},        // { dbId: [记录...] }
  loaded: {},      // { dbId: true/false }
  load: function (dbId) { /* 单表加载，带重试 */ },
  get: function (dbId) { return this.rows[dbId] || []; },
  loadAll: function () { /* 批量加载，返回失败表列表 */ }
};
```

**`loadAll()` 的设计演进值得记录**。最初版本用 `Promise.all` 同时发起 7 张表的请求——结果在表增加到 16 张时，**并发太高被限流，全部失败**。用户看到的现象是"所有数据都空了"，一度以为数据丢了。

现在的做法：

1. **分批**发起（每批 4 张）
2. 每张表**独立重试**（最多 2 次，间隔递增）
3. **返回失败表的清单**
4. 页面上明确渲染成「**3 张表未加载 · 点重试**」

> 关键认知：**"加载失败"和"没有数据"必须视觉上区分开**。混为一谈会让人误以为数据丢失，是灾难性的体验问题。

## 六、表单引擎（区块 ⑤）

### `openSheet(title, html)` —— 底部弹层

移动端的通用弹层。`#mask` + `#sheet` 两个元素，配 CSS transition。

### `formHTML(fields, props)` —— 通用表单渲染

`fields` 是字段描述数组：

```js
[
  { k: '名称', label: '名称', type: 'text', required: true },
  { k: '金额', label: '金额', type: 'number' },
  { k: '缴费周期', label: '周期', type: 'select', opts: ['月','季','半年','年'] },
  { k: '下次应缴日', label: '下次应缴日', type: 'date' },
  { k: '备注', label: '备注', type: 'textarea' }
]
```

**关键规则**：`opts` 如果是函数，必须在渲染时调用：

```js
var opts = typeof f.opts === 'function' ? f.opts() : (f.opts || []);
```

### `formProps(fields)` —— 从 DOM 收集值

按 `type` 转成平台需要的格式：

```js
switch (f.type) {
  case 'number':   props[f.k] = { number: numOf(el.value) }; break;
  case 'date':     props[f.k] = { date: el.value }; break;          // 'YYYY-MM-DD'
  case 'select':   props[f.k] = { select: el.value }; break;
  case 'multi_select': props[f.k] = { multi_select: [...] }; break;
  default:         props[f.k] = { text: el.value };
}
```

### `hubForm(key, id)` —— 声明式 CRUD 的保存逻辑

**这里有一个重要修正**。最初的写法是：

```js
// ❌ 错误写法
if (!id && cfg.defaults) {
  for (var k in cfg.defaults) props[k] = cfg.defaults[k];
}
```

问题：新增记录时**无条件**套用默认值，把用户刚填的内容覆盖了。实际事故——给两只宠物各新增一条护理记录（一条选宠物 A、一条选宠物 B），结果两条都变成了宠物 A，而且用户选的日期也被改成今天。

正确写法：

```js
// ✅ 正确写法：只补空，不覆盖
var dft = cfg.defaults && cfg.defaults();
if (dft) {
  for (var k in dft) {
    if (!props[k]) props[k] = dft[k];     // 只在用户没填时补
  }
}
```

> **推广原则**：任何"默认值"逻辑都必须遵守"只补空"。

## 七、业务配置 HUB（区块 ⑥）

这是本项目**最值得借鉴的设计**。

与其为每张表写一套增删改查，不如**用配置描述表**，让一套引擎渲染所有表：

```js
var HUB = {
  FEE: {
    dbId: DB.FEE,
    title: '固定费用',
    addLabel: '新增费用',
    fields: [
      { k: '名称', label: '名称', type: 'text', required: true },
      { k: '金额', label: '金额', type: 'number' },
      { k: '缴费周期', label: '周期', type: 'select', opts: ['月','季','半年','年'] },
      { k: '下次应缴日', label: '下次应缴日', type: 'date' },
      { k: '状态', label: '状态', type: 'select', opts: ['待缴','已缴'] }
    ],
    defaults: function () { return { '状态': { select: '待缴' } }; },
    sort: function (a, b) { /* 按到期日升序 */ },
    row: function (r) { /* 渲染列表行 */ },
    quick: function (id) { /* 快捷操作：标记已缴 + 推算下次应缴日 */ }
  },
  FES: { /* 节日与生日 */ },
  DLY: { /* 日用品库存 */ }
};
```

引擎部分：

```js
function renderHub() {
  var cfgs = { fee: HUB.FEE, fes: HUB.FES, dly: HUB.DLY };
  // 每个配置渲染成一个面板，复用同一套行渲染和表单
}
```

**注意 `defaults` 写成函数而不是对象字面量**。原因是本文档前面说过的坑：如果写成数组/对象字面量，其中引用的动态数据（如 `roomList()`）会在模块加载时求值为空。所以**凡是 options 或默认值来自数据，一律写成函数**。

### `quick()` 示例：费用标记已缴

```js
quick: function (id) {
  var rec = recOf(DB.FEE, id);
  var cycleMap = { '月': 1, '季': 3, '半年': 6, '年': 12 };
  var m = cycleMap[rec['缴费周期']] || 12;
  var cur = parseDay(rec['下次应缴日']);
  var nd = new Date(cur.getFullYear(), cur.getMonth() + m, cur.getDate());
  return db.updateRecord({
    databaseId: DB.FEE, recordId: id,
    properties: { '下次应缴日': { date: fmtD(nd) }, '状态': { select: '待缴' } }
  });
}
```

一次点击完成"标记已缴 + 滚动到下一期"。

## 八、渲染函数（区块 ⑦）

### 视图切换

5 个视图都是 `<div id="v-xxx">`，`switchTab(name)` 控制 `display`。

### `renderMe()` —— 我的页面

含四个特殊功能：

- `exportJSON()` —— 把 Store 里所有表导出成一个 JSON 文件下载
- `snapNow()` —— 把全表数据打成一条快照存进「数据快照」表
- `pruneSnaps()` —— 只保留最近 N 条快照
- `resetAdminPw()` —— 重置管理员密码

**`snapNow()` 的坑**：快照要覆盖**所有**表，所以有一个 `SNAP_NAMES` 名单。**每次加新表都必须同步更新这个名单**，漏掉就等于这张表没有备份。

## 九、事件与订阅（区块 ⑧）

### `bind()` —— 事件委托

不用给每个按钮单独绑事件，而是委托到容器：

```js
function bind() {
  document.addEventListener('click', function (e) {
    var el = closest(e.target, '[data-act]');
    if (!el) return;
    var act = el.getAttribute('data-act');
    var id = el.getAttribute('data-id');
    // 分发到具体处理函数
  });
}
```

好处：动态渲染出来的元素**不需要重新绑定**。

### `subscribe()` —— 实时同步

```js
function subscribe() {
  var timer = null;
  db.onUpdated(function () {
    clearTimeout(timer);
    timer = setTimeout(resync, 400);      // 防抖 400ms
  });
}
```

多个端同时打开时，一端改了数据，另一端自动刷新。**防抖是必需的**——否则批量写入会触发几十次重渲染。

### `renderSync(state, text)` —— 同步状态指示

三种状态：`ok`（已同步）/ `load`（同步中）/ `off`（离线或失败）。左下角常驻显示。

## 十、启动流程（区块 ⑨）

```js
function boot() {
  bind();

  // 【分支 1】无 SDK → 离线预览，只渲染不读写
  if (!db) {
    renderSync('off', '离线预览');
    $('tdBanner').innerHTML = '<div class="banner"><b>离线预览</b>...</div>';
    return;
  }

  // 【分支 2】正常云端模式
  renderSync('load', '同步中');
  db.getSchema({ databaseId: DB.MAINT })
    .then(function (schema) {
      // 关键：从 schema 读房间等选项，不硬编码
      (schema.properties || []).forEach(function (f) {
        if ((f.type === 'select' || f.type === 'multi_select') && f.config && f.config.options) {
          MAINT_OPTS[f.name] = f.config.options.map(function (o) { return o.text; });
        }
      });
    })
    .catch(function (e) { console.error('[schema]', e); })   // 失败不阻塞，用兜底选项
    .then(function () {
      // 渲染房间下拉框
      var rooms = MAINT_OPTS[MF.ROOM] || FALLBACK_OPTS[MF.ROOM];
      $('roomSel').innerHTML = '<option value="">全部房间</option>' +
        rooms.map(function (r) { return '<option>' + esc(r) + '</option>'; }).join('');
      return Store.loadAll();
    })
    .then(function (fails) {
      // 展示加载失败情况（区分"失败"与"空"）
      var nf = (fails || []).length;
      if (nf) renderSync('off', nf + ' 张表未加载 · 点重试');
      else renderSync('ok', '已同步');

      renderToday(); refreshMaint(); renderHub(); renderAi(); renderMe();

      // 首次进入必须选成员
      var nm = user();
      if (!nm || !memberOf(nm)) openMemberSheet(true);
      else if (isAdminMember(nm) && !adminTrusted()) openMemberSheet(true);

      subscribe();
    })
    .catch(function (e) { console.error('[boot]', e); });
}
```

**注意 `.catch()` 的位置**：schema 读取失败后接 `.catch()` 再 `.then()`，这样失败**不会中断**后续流程，只是退回兜底选项。这是"容错"原则的体现。

## 十一、演示环境（`demo/`）

演示环境让页面**不需要平台也能跑起来**。

### 组成

### 原理

页面主脚本读 SDK 的方式是：

```js
var db = (window.__SMART_PAGE__ && window.__SMART_PAGE__.database) || null;
```

`mock4.js` 在主脚本**之前**执行，塞进一个假的 `__SMART_PAGE__`：

```js
window.__SMART_PAGE__ = {
  database: {
    query: function (a) {
      var rows = DATA[a.databaseId] || [];
      return new Promise(function (res) {
        setTimeout(function () {
          res({ records: rows.slice(0, a.pageSize || 100), hasMore: false });
        }, 30);                                  // 模拟网络延迟
      });
    },
    getSchema: function () { return Promise.resolve(SCHEMA); },
    addRecord: function (a) { /* 写入内存 DATA */ },
    updateRecord: function (a) { /* 更新内存 DATA */ },
    deleteRecord: function (a) { /* 删除内存 DATA */ },
    uploadImage: function () { return Promise.resolve({ url: '' }); },
    onUpdated: function (cb) { /* 空实现 */ }
  }
};
```

于是页面以为自己在正常云端模式，全部交互都可点，只是数据存内存、刷新即失。

### 虚构数据的覆盖范围

`mock4.js` 里的 `DATA` 覆盖了 12 张表（比页面主配置的 7 张更多），包括宠物档案（一只叫"示例宠物"的猫）、宠物护理、物品归档、存放位置、设备档案等扩展模块。

### 另一个降级路径

即使不注入 mock，**直接打开 `index.html`** 也会走离线分支（`if (!db)`），只是没有数据、界面是空的。所以如果你想看"完全空白的初始状态"，直接开 `page_v9/index.html` 就行。

## 十二、代码阅读建议

如果你要动手改，按这个顺序读效率最高：

1. **先看 `DB` / `MF` 配置块**（约 319-400 行）—— 知道有哪些表、哪些字段
2. **再看 `Store`**（约 700-820 行）—— 理解数据怎么进来
3. **再看 `HUB.FEE`**（约 1000 行起）—— 理解声明式 CRUD 的套路，其他表照抄
4. **最后看 `boot()`**（文件末尾）—— 理解整体启动顺序
5. **渲染函数**按需查阅，不必通读

改动的常见落点：

| 想做什么 | 改哪里 |
|---|---|
| 加一个字段 | `MF` 常量 + 对应 `HUB.*.fields` + 渲染函数 |
| 加一张新表 | `DB` 常量 + `HUB` 配置 + `SNAP_NAMES` + `Store.loadAll` 的表清单 |
| 改提醒阈值 | `mStatus()` 的分档条件 |
| 改界面样式 | CSS 区块（约 8-183 行） |
| 改 AI 规则 | **不改代码**，改数据表「AI任务注册表」的 `指令全文` |

最后一条是这套架构最大的好处：**业务规则的调整不需要碰代码，也不需要重新部署。**
